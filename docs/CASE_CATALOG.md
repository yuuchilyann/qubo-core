# 案例目錄

參考案例集的資料與勾稽狀態。全部由 `npm run verify` 逐項檢查。

每個案例另外帶一段**情境**（做什麼用的、`x` 代表什麼、真實應用），存在 i18n 字典裡
而不是案例定義裡：那是簡報文案，不是勾稽資料，不該和 `paperQ` 放在同一個檔案。
對照表見下。

## 資料模型

每個案例宣告的是**原始約束模型**與論文套用的懲罰規則，Q 由 `derive()` 算出來。
論文印出的 Q 另存 `paperQ`，只用來做 diff。

```ts
type QuboCase = {          // 論文算例；ALL_CASES 只收這種
  source: 'worked'
  section: string          // '§5.2'
  pages: [number, number]  // 勾稽錨點
  model: ConstrainedModel  // 目標式 + 約束 + 每條約束用哪個懲罰配方
  penalty: { paperValue, min, max, step } | null
  paperQ: number[][]       // 只用於比對，永不參與計算
  paperConstant: number
  paperSolution: { x, yQubo, yOriginal }
}
```

`yOriginal = yQubo + constant` 這個不變式對每個案例都成立，也被 harness 斷言；
論文本身就是成對引用這兩個值的（例如 §5.4：「Solving QUBO gives y = −982 … we get
the original objective function value of 1200 − 982 = 218」）。

另一種是 `ExtendedCase`（`source: 'mentioned'`），給論文**只點名、沒有算例**的問題，
見下方「延伸案例」。它刻意**沒有** `paperQ`。兩者合稱 `CatalogCase`，完整目錄是
`CATALOG = [...ALL_CASES, ...EXTENDED_CASES]`。

`ALL_CASES` 維持只收論文算例，因為下游消費端會逐一讀它的 `paperQ`。

## 懲罰配方

| `method` | 對應 | 公式 |
|---|---|---|
| `transform1` | §5 通用配方 | `P(a·x − b)²`（需先用 slack 補成等式） |
| `transform2` | §5 特例 | `Σ_{j∈S} x_j ≤ 1` → `P Σ_{i<j∈S} xᵢxⱼ`（p.10 表格第 1、5 列） |
| `atLeastOne` | p.10 第 2 列 | `xᵢ + xⱼ ≥ 1` → `P(1 − xᵢ − xⱼ + xᵢxⱼ)` |
| `exactlyOne2` | p.10 第 3 列 | `xᵢ + xⱼ = 1` → `P(1 − xᵢ − xⱼ + 2xᵢxⱼ)` |
| `implication` | p.10 第 4 列 | `xᵢ ≤ xⱼ` → `P(xᵢ − xᵢxⱼ)` |
| `equal2` | p.10 第 6 列 | `xᵢ = xⱼ` → `P(xᵢ + xⱼ − 2xᵢxⱼ)` |

最小化時懲罰**相加**，最大化時**相減**（§5.3、§5.5）。

### 子句與高次項降階（§4.3、§7 第 4 點）

子句不是約束，而是**目標函數本身**：每條被違反的子句計 1，權重不隨 P 變動。
子句的懲罰是各文字「為假」指示函數的乘積，兩個文字是二次（§4.3），三個以上就是高次。

`derive()` 先把**所有子句加總**，再對剩下的三次以上項套用 Rosenberg 降階：
把 `x_a x_b` 換成新的二元變數 `y`，並加上懲罰 `P(x_a x_b − 2x_a y − 2x_b y + 3y)`，
它在 `y = x_a x_b` 時為 0、否則至少為 P。先加總再降階的好處是：互相抵消的高次項
（例如 Not-All-Equal 的兩條子句）不會產生多餘的輔助變數。

降階的順序是確定的：先進先出、每次取最小的兩個變數索引，同一對變數重複使用同一個 `y`。
每個 `y` 記錄它的 `load`（被它取代的各項 |係數| 總和）。**P 大於最大的 load，
降階就在每個最優解上精確**；P 等於 load 時會出現 `y ≠ x_a x_b` 的平手解。

這個界在 500 個隨機子句模型上驗證過（最長 5 個文字、最多 17 個輔助變數）：
P = 最大 load + 1 時零錯誤；P = 最大 load 時有 95 個模型出現平手解；Python 與 TypeScript
的 Q 全部一致。

## 延伸案例（論文只點名的問題）

論文 §1（pp.3–4）列了二十多種「QUBO 涵蓋的問題」，§6 也提到幾種，但只有 §2–§5.5
這十一個有算例。其餘的問題論文**沒有給實例、沒有印 Q、也沒有答案**。

延伸案例的實例是本庫自己選的，所以沒有東西可以 diff。替代的參照是**約束窮舉**，
它不經過 `derive()`。`verifyExtended()` 斷言：

| 檢查 | 證明什麼 |

| 原始模型有可行解 | 實例本身有答案 |
| QUBO 最優 + 常數 == 約束窮舉最優 | 推導正確，且懲罰把最優值留在可行解上 |
| 每個 QUBO 最優解都可行 | P 夠大：沒有不可行解與最優值打平 |
| QUBO 簡併度 == 約束窮舉簡併度（無 slack 時） | 兩邊的最優解一一對應 |
| 約束窮舉最優 == `anchor`（若有） | 把實例接回論文**有**印出的某個數字 |

### P：保證夠大的界 vs. 實際門檻

延伸案例的 P 都附一個**推得出來的充分界**，寫在案例註解裡；實際能用的最小 P 通常小得多。
這正是論文 p.13 說的「Goldilocks 區間」相當寬：

| id | 充分界 | 本庫取 | 實測最小可用 P（滑桿刻度上） |
|---|---|---|---|
| `max-independent-set` | P > 1 | 2 | 2 |
| `max-clique` | P > 1 | 2 | 1（這張圖上 P = 1 恰好沒有打平） |
| `max-diversity` | P > 170（最大列和） | 200 | 60 |
| `discrete-tomography` | P > 0 | 1 | 1 |
| `task-allocation` | P > 15 | 16 | 8 |
| `capital-budgeting` | P > 13（全選的價值；不選可行為 0） | 14 | 1 |
| `multiple-knapsack` | P > 13 | 14 | 5 |
| `p-median` | P > 9（某個可行方案的成本） | 10 | 3 |
| `warehouse-location` | P > 16（全開的成本） | 17 | 6 |
| `linear-ordering` | P > 4（最高可能 10 − 可行排序 6） | 5 | 1 |
| `clique-partitioning` | P > 9（單一節點的 \|權重\| 總和） | 10 | 3 |
| `max-3-sat` | P > 2（輔助變數的 load） | 3 | 2 |
| `graph-partitioning` | P > 2（節點 1、2 一組的割邊數） | 3 | 1 |
| `portfolio` | P > 39（前三檔的目標 26 − 最低可能 −13） | 40 | 4 |
| `max-matching` | P > 5（最大邊權） | 6 | 3 |
| `community-detection` | P > 33（單一節點的 \|權重\| 總和） | 34 | 1 |
| `shortest-path` | P > 10（S→B→T 的長度） | 11 | 4 |
| `travelling-salesman` | P > 21（1→2→3→4→1 的長度） | 22 | 7 |
| `traffic-flow` | 原論文的 λ 規則：單一車輛出現的路段成本項數最大值 7 | 7 | 3 |

兩種推界方式值得分開看：

- **最小化、目標非負**（P-Median、Warehouse Location）：任何不可行解至少被罰 P、目標至少 0，
  所以 P 只要大於**某一個可行方案**的成本就夠，不需要知道最優解。
- **最大化**（Capital Budgeting、Multiple Knapsack、Linear Ordering）：P 大於
  「所有變數取 1 時的最高可能目標」減去「某一個可行方案的目標」。

本庫取的是充分界，不是實測門檻：實測值依賴實例，換一組資料就可能不夠。

### Max Independent Set — 同一張圖，答案由 §4.1 推得

沿用 §3.2／§4.1 的 5 點圖。每條邊 `xᵢ + xⱼ ≤ 1` 是 p.10 表格第 1 列，也就是 §4.2 用的
`P·xᵢxⱼ`，p.10 說 Pardalos & Xue 把它用在 maximum clique「and related problems」。

獨立集的補集恰好是頂點覆蓋，所以 α(G) = n − τ(G) = 5 − 3 = 2，其中 3 是 §4.1 印出的
答案。論文沒寫這個 2，但它由論文印出的數字推得，這就是 `anchor`。

P 由本庫決定：同時選一條邊的兩端，目標 +1、懲罰 −P，所以 `P > 1` 才保證嚴格較差。
`P = 1` 時有 3 個不可行解與最優值打平（簡併度 7 而非 4），harness 的負面測試會抓到；
滑桿可以讓讀者親眼看到這件事。

### Max Clique — Max Independent Set 換成非邊

同一張圖，約束改成每一條**不存在的邊** `xᵢ + xⱼ ≤ 1`：團裡任兩點都要相鄰。
也就是補圖上的最大獨立集。圖中唯一的三角形是 3–4–5，最優值 3、唯一解。

### Max Diversity — 沿用 §3.1 的八個數字

`dᵢⱼ = |sᵢ − sⱼ|`，選恰好 4 個。目標本來就是二次的，唯一的約束是基數 `Σxⱼ = 4`。
最優解唯一：{7, 10, 31, 42}，總距離 126。直線上的點，兩個端點必選，中間兩個要拉得最開。

### Discrete Tomography — 投影決定不了影像

3×3 影像，列和與行和都是 (2, 1, 2)，也就是「X」形的投影。沒有目標函數。
窮舉找到 **5 張**影像有相同的投影，解空間分頁的簡併度就是這個案例的重點：
只給投影，影像無法唯一還原，這正是真實斷層重建的核心難題。

### Task Allocation — 執行成本與通訊成本互相拉扯

3 個任務、2 台處理器。全部放同一台可以省掉所有通訊（最好 16），但最優解是拆開：
任務 1、3 在處理器 1，任務 2 在處理器 2，總成本 14，唯一。

### Capital Budgeting — §5.5 去掉二次項、多一個預算期

價值沿用 §5.5 的線性係數 (2, 5, 2, 4)，第一期預算就是 §5.5 那一列 `8, 6, 5, 3 ≤ 16`，
第二期 `3, 7, 4, 6 ≤ 13` 是本庫加的。只有第一期時最好是選 2、3、4（價值 11），
第二期把它排除，最優解變成 2、4（價值 9），唯一。

slack 上界用整列範圍（16、13），**不能**沿用 §5.5 的判斷 3：最優解第一期剩下 7，
上界 3 表示不了。這正好說明 §5.3／§5.5 的 slack 上界是針對那一題的判斷，換一題就要重新判斷。

### Multiple Knapsack — 一題用兩種變換

「每個物品最多放一個背包」是 p.10 表格第 1 列（Transformation #2，不需 slack），
容量是 `≤` 加 slack（Transformation #1）。物品沿用 §5.5 的四個專案，容量 10 和 8 是本庫的。
總重 22 超過 18，一定有東西放不進去；最優價值 11，有 4 種不同裝法。

### P-Median 與 Warehouse Location — 第一次用到 p.10 第 4 列

`x_{ij} ≤ y_j`（客戶 i 只能由已開的據點 j 服務）是 p.10 表格第 4 列 `P(x_{ij} − x_{ij}y_j)`。

**變數順序有講究**：`implication` 配方依索引順序取兩個變數當「前件 ≤ 後件」，
不看係數正負，所以所有 `x_{ij}` 必須排在 `y_j` 前面。排反了，約束窮舉的檢查會失敗。

同一組點：P-Median（恰開 2 個）開最外側的據點 1、3，總距離 5；
Warehouse Location 加上開設成本 (4, 1, 6)、不限個數，便宜的中間據點改變了答案：開 1、2，總成本 14。

**與原作者做法的交叉印證。** §1 清單的出處 Kochenberger & Glover（2006）§5.1 處理同一類問題
（Warehouse Location: Single source, Uncapacitated）時，是把 `y` 取補數，再對
`x_{ij} + ȳ_i ≤ 1` 套 Transformation #2，得到 `P·x_{ij}(1 − y_i)`。展開就是
`P(x_{ij} − x_{ij}y_i)`，和本庫用的 p.10 第 4 列逐項相同，也同樣「不需要新變數」。
該文的實例是隨機產生的（`c_ij = U(50, 100)`、`f_i = U(100, 200)`、P = 200），
所以能比對的是配方，不是數字。

### Linear Ordering — slack 上界 1 是判斷，而且被驗證

每對 `i < j` 一個變數，每個三元組 `i < j < k` 兩條列 `0 ≤ x_{ij} + x_{jk} − x_{ik} ≤ 1`。
每條列的 slack 上界取 1，低於整列範圍 2：只要另一條列成立，這條列的 slack 就不會超過 1。
這和 §5.3 的上界判斷是同一回事；約束窮舉（完全不知道 slack）確認這個判斷沒有漏掉任何合法排序。

目標是**淨一致數** `Σ (w_{ij} − w_{ji}) x_{ij}`。完整的一致數還要加常數 `Σ_{i<j} w_{ji} = 12`，
約束模型沒有放常數的地方，所以由站台的問題檢視補回。多數決是循環的（1 勝 2、2 勝 4、4 勝 1），
傳遞性約束因此真的起作用；最佳排序 4, 1, 2, 3，淨值 9（一致 21／30），唯一。

### Clique Partitioning — §7 第 3 點的點變數置換

標準模型每條**邊**一個變數。§7 第 3 點把「i 與 j 同組」換成 `Σ_k x_{ik}x_{jk}`，
目標變成二次、約束只剩「每個點恰好一組」。4 個點給 4 個組，所以不排除任何分法。
最優是 {1, 2} {3, 4}，總權重 7；它以 **12 個**最優解出現，因為組的標籤可以互換（4 × 3）。

### Max 3-SAT — 第一個需要輔助變數的案例

8 條三文字子句、4 個變數，恰好一組賦值全部滿足（`x₁ = 1`，其餘為 0）。
加總後只剩兩個三次項 `−x₁x₂x₃`、`−x₁x₂x₄`，都含 `x₁x₂`，所以只需要一個輔助變數 `x₅`，
Q 是 5×5。P 是降階懲罰：`x₅` 的 load 是 2，所以 `P > 2`，取 3。
負面測試：P = 1 時最優值仍是 0，但出現 `x₅ ≠ x₁x₂` 的平手解；P = 0 時連最優值都錯。

### CSP（Not-All-Equal）— 三次項全部抵消

六個人分兩隊，六組三人組各自不能全在同一隊。每組三人是兩條子句 `(a ∨ b ∨ c)`、
`(¬a ∨ ¬b ∨ ¬c)`，各自是三次，但三次項一正一負**互相抵消**，整組約束是二次的
`1 − a − b − c + ab + ac + bc`。因為先加總再降階，這題**一個輔助變數都沒有**，
和 Max 3-SAT 恰成對比。8 種分隊方式全部滿足（交換隊名算 2 種，所以本質上 4 種）。

**這不是原作者用的 CSP 寫法。** Kochenberger & Glover（2006）§5.2 的 CSP 是線性等式組
`Ax = b`，`a_ij ∈ {−1, 0, 1}`、`b_i ∈ {1, 2}`，以 Transformation #1、P = 2 轉換，
不需要新變數。Not-All-Equal 同樣是 CSP，但是另一種；本庫選它，是因為「三次項互相抵消」
這件事是 Max 3-SAT 單獨教不了的。該文的實例是隨機產生的，兩種寫法都沒有可重現的公開實例。

### §6 引用的問題（`mention: 'cited'`）

§1 清單之外，§6 在引用他人研究時也提到幾個問題。這類案例的出處比 §1 更間接（論文只說
「某研究把 QUBO 用在這個問題上」），所以標成 `mention: 'cited'`，站台的說明框與產出的
Python 都會寫「cited」而不是「named」。

- **Graph Partitioning**（p.32，Mniszewski 等）：§3.2 同一張圖，分成 2 個與 3 個節點兩組、
  割邊最少。Max-Cut 最大化得 5，這裡最小化得 2：{1, 2} 對三角形 {3, 4, 5}。
- **Portfolio**（p.32，Elsokkary 等）：二元 Markowitz，恰好持有 3 檔、最小化「風險 − 報酬」。
  報酬最高的 2、4、5 風險太高；最優是 3、4、5。基數約束**真的起作用**：不加約束時最好只持有
  3、5 兩檔。初稿要求持有 2 檔，那個無約束最優解剛好滿足約束，P = 0 也能通過，等於沒有示範
  到懲罰，所以改成 3 檔。原作者之一的 Kochenberger & Ma（2019）白皮書未公開，這裡用的是
  教科書寫法。
- **Max Weight Matching**（p.31，Lucas 的清單）：每條**邊**一個變數，每個節點最多接一條，
  度數 2 的節點用 p.10 第 1 列，度數 3 的用一般形式（第 5 列）。最優 {1–2, 3–4}，權重 9。

- **Community Detection**（p.32、p.34，Negre 等）：k 個社群的模組度最大化，與 Negre 等的形式相同。
  模組度是分數，所以目標乘上 (2m)² 讓係數全是整數：`Σ_{i<j} (2m·A_ij − k_i k_j) Σ_k x_{ik}x_{jk}`，
  站台再換算回 `Q = (2·目標 − Σk_i²)/(2m)²`。兩個三角形加一座橋，最優就是兩個三角形，Q = 5/14。
- **Shortest Path**（p.31，Pakin）：標準的流量守恆寫法，**不是** Pakin 的迷宮編碼。每條弧一個變數，
  每個節點「流出 − 流入」等於 +1（S）、−1（T）或 0。最短路徑 S→A→B→C→T 長 6，弧數反而最多。
  圖是無環的，所以不會出現與路徑分離、自行滿足約束的迴圈。
- **Travelling Salesman**（p.32，車輛路徑：Feld、Clark、Ohzeki 等）：引用的是車輛路徑問題，
  這裡做的是它的單車、無容量核心，也就是 TSP。城市 1 固定在第一位，消掉每條路線的 4 種旋轉，
  變數從 16 降到 9。最短 1→2→4→3→1 長 18，正反兩向各算一個。
- **Traffic Flow**（p.32，Neukart 等）：**照原論文的 QUBO**：每輛車三條候選路線、擁塞是每個路段
  車數的平方和、每車恰好一條路線。λ 也照原論文的規則（單一車輛出現的路段成本項數最大值，這裡是 7），
  不是本庫推的界；約束窮舉確認它足夠。原本三輛車都走 c、d 路段，擁塞 19；最優擁塞 5。

### 論文清單中沒有實作的三項

§1 清單裡的 Asymmetric Assignment、Symmetric Assignment、Side Constrained Assignment
**刻意不做**。追溯過的來源：

| 來源 | 結果 |
|---|---|
| Kochenberger & Glover（2006）§4（§1 清單的出處） | 只列名稱，與 2019 論文幾乎逐字相同，沒有定義 |
| 同文引用的 Boros & Hammer（1991）、Lewis 等（2004） | 主題分別是 Max-Cut、任務分配，無關 |
| Kochenberger 等（2014）綜述 | 只提到「various forms of assignment problems」 |
| Kochenberger 等（2004，OR Spectrum） | 非公開，未能確認 |

這三個名稱在文獻中沒有唯一定義。自行選一個定義再標成「論文提及的問題」，
會把本庫的判斷冒充成論文的內容，所以在找到原作者的定義之前不收。


### §3.1 Number Partitioning — 「自然形式」其實是通用配方的特例

論文從 `diff²` 手推，本站表達成 `transform1` 套在平衡等式 `Σsⱼxⱼ = c/2` 上、`P = 1`。
展開後對角線是 `sⱼ² − c·sⱼ = sⱼ(sⱼ − c)`、非對角線是 `sᵢsⱼ`，與 p.7 印出的完全一致。

### §4.3 Max 2-SAT — 唯一有 ±½ 的 Q

子句 `(l₁ ∨ l₂)` 只有在兩個 literal 都為假時才違反，所以懲罰是兩個「為假」指示函數
的乘積：`x_v` 為假 ⇒ `(1 − x_v)`、`¬x_v` 為假 ⇒ `x_v`。展開這個乘積會自動生出 p.15
表格的全部三種情形，不需要 case 分析。

`−x₂x₃` 這種孤立的二次項在對稱形式下要對半拆到兩格，所以出現 ∓½。切到上三角形式就
變回整數。

### §5.2 Graph Colouring — 唯一同時用兩種變換

節點指派方程用 `transform1`，相鄰限制用 `transform2`。Q 的區塊對角結構（五個 3×3）
在熱圖上一眼可見，正是論文 p.23 說的「Looking for patterns is often a useful
de-bugging tool」。

沒有目標函數，任何正的 P 都可以。可行的 3-著色恰好有 6 種（節點 2 與其餘全鄰接，
剩下的路徑 1-5-4-3 用兩色只有 2 種著法，3 × 2 = 6）。

### §5.3 / §5.5 slack 上界是論文的判斷，不是推導

| 約束 | 論文取的上界 | 該列理論上限 |
|---|---|---|
| §5.3 `2x₁+2x₂+4x₃+3x₄+2x₅ ≤ 7` | 3 | 7 |
| §5.3 `3x₁+3x₂+2x₃+4x₄+4x₅ ≥ 5` | 6 | 11 |
| §5.5 `8x₁+6x₂+5x₃+3x₄ ≤ 16` | 3 | 16 |

論文原文是「estimating a reasonable value for how large the slack activity could be」
（p.25），所以 `slackBound` 在案例定義裡是**明寫的資料**而不是算出來的。
「建模推導」分頁會把兩個數字並列，讓讀者看見這個判斷。

二進位展開用單純的 2 的冪次：`k = ⌊log₂U⌋ + 1` 個位元，權重 1, 2, 4, …。
所以 `U = 6` 會得到 1+2+4（可達 7，略微超覆蓋），這正是論文 p.25 的做法。

### §5.4 QAP — 論文的目標函數式子有排版錯誤

p.28 印出的目標函數與 p.29 印出的 Q 矩陣互相矛盾：

| 論文式子 | 應為 | 依據 |
|---|---|---|
| `60x₂x₇` | `32x₂x₇` | Q[1][6] = 16 ⇒ 係數 32 |
| （遺漏） | `48x₅x₇` | Q[4][6] = 24 ⇒ 係數 48 |
| （遺漏） | `90x₆x₇` | Q[5][6] = 45 ⇒ 係數 90 |

窮舉所有「設施不同且位置不同」的配對會得到 **18** 個二次項，而非式子列出的 16 個。
本站從流量矩陣 F 與距離矩陣 D 重新推導（`x_{ik}·x_{jl}` 的係數是 `2·f_{ij}·d_{kl}`），
結果與論文印出的 **Q 矩陣**逐格相符，也重現論文自己的答案 218。

換句話說：Q 矩陣是對的，它上面那行式子有排版錯誤。這是「推導而非抄寫」的直接回報。

## 新增案例的步驟

### 論文算例

1. 在 `src/cases/` 對應的 group 檔裡加一個 `QuboCase`（`source: 'worked'`）
2. 填 `model`（原始約束模型）、`paperQ`、`paperConstant`、`paperSolution`
3. 加進 `src/cases/index.ts` 的 `ALL_CASES`
4. 在 `src/i18n/locales/zh.tsx` 加四個情境字串（`case.<id>.name` / `.scenario` /
   `.xMeans` / `.uses`），並在 `src/components/CaseScenario.tsx` 的 `SCENARIOS`
   註冊。鍵是明寫的，漏掉會是編譯錯誤而不是頁面上一行原始 key
5. `npm run verify:all` — 三道驗證都要綠

如果 `derive()` 算不出 `paperQ`，**先懷疑 `model` 宣告錯了**，不要去改 `paperQ`。
`paperQ` 是外部真值，不是可以調整到符合的參數。

### 延伸案例

7. `npm run verify:all`
